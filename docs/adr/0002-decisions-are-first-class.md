# 决策是事内一等但按需累积的事件

## Status
accepted (revised 2026-11-27)

## Context

复杂长周期工作续接时，人真正需要的是「为什么变成现在这样」（方案 A 被否、方案 B 上位、B 又回退），而不是 300 轮流水账；交接时如果丢失已否决方案，新 agent 会反复踩坑。但对只聊了 3 轮就修完的小事，强行要求填“决策序列”只会制造空洞废话。

## Decision

每件「事」的最小闭环是「目标 + 状态 + 现状/卡点 + 唯一一个下一步」，保证小事极轻、3 秒可读；「决策」依然建模为事内一等事件（含轮次证据与 `supersede` 取代关系），但只在发生方案选择、方向变更、放弃、回退或关键拍板时**按需累积**。

## Considered Options

- **所有事强制围绕决策序列组织**：对简单任务过重，容易逼着模型编造伪决策。
- **放弃一等决策实体，只留备注/摘要**：表达不了「B 取代 A」的演化关系，复杂工作跨会话与交接时会重新踩旧坑。

## Consequences

- 数据模型保留独立的 decision 实体与 supersede 关系，但允许某件「事」的 decisions 列表为空。
- 窄抽屉默认 4 行卡片只展示「标题与状态 / 当前卡点 / 下一步 / 动作条」，决策序列与跨会话段清单放在展开详情与交接包中呈现。

# 双态推断、拐点轻确认与“一次盘点 + 增量挂载”

## Status
accepted (2026-11-27)

## Context

会话日志里天然没有“事、状态、下一步”字段。如果强制人工逐条维护，用户忙时不会点，面板迅速荒废；如果允许模型每天全盘静默洗牌，用户已经建立的记忆锚点会被频繁改写，且容易误改已完结老事或被子代理会话噪音淹没。

## Decision

采用「规则保底 + 模型后台异步提炼物化缓存」的双层引擎，并把生命周期拆成三条铁律：

1. **双态展示 + 拐点确认**：系统自动推断的「事、状态、下一步、决策」以「推测态」默认直接可见（打开抽屉直接读物化快照、首帧秒出）；仅在三个自然拐点（切换话题、疑似收尾/卡住、重返未收束会话）弹出非阻塞轻条，用户点一下即转「已确认态」锁定，系统永不覆盖。超过可配置无活动天数（默认 14 天）的推测态事自动沉降进「已搁置」。
2. **存量一次盘点 + 增量永不洗牌**：工作区首次冷启动（或用户手动触发重新盘点）一次性用硬信号（分叉血缘、引用句柄、共同改动文件）叠加模型语义扫描存量，产出草稿并给 30 秒轻核对台；核对锁定后切入增量模式，新会话只按「L1 硬血缘 → L2 文件重叠 → L3 同工作区未收束事语义匹配」挂载。
3. **三条防污染边界**：子代理/自动化会话默认排除在自动立事之外；撞上已锁定「已完成」的旧事时不静默篡改，只提示是否关联重开；同一件事允许挂多个并行活跃会话并按工作区串行防抖更新。

## Considered Options

- **纯人工建单与维护**：准确但冷启动与维护成本过高，实际无人坚持。
- **后台每日全工作区重新聚类**：省事但会反复打乱用户认知锚点，破坏可信度。
- **强依赖模型同步计算**：打开抽屉时等待慢，且无模型或断网时核心页签瘫痪。

## Consequences

- 物化快照落盘在 `~/.dsh/topic-map/`，以会话日志为唯一事实源，可随时重建；用户确认与锁定数据独立分表存储，绝不被重建覆盖。
- 存量扫描原型完成后，必须先在真实工作区历史数据上执行只读干跑（dry-run）抽检分类与合并准确度，补齐长尾边界场景。

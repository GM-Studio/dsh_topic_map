# 三层防失真续接与交接协议

## Status
accepted (2026-11-27)

## Context

工作续接有两个现实出口：回到原会话继续聊（原会话可能已串台聊了别的事或上下文过长），或者新开会话让空白 agent 接手。如果只靠模型写一段自由散文摘要粘贴过去，路径、报错、已否决方案极易丢失或失真；如果直接贴全量历史，又会撑爆上下文窗口。

## Decision

原会话续接与新开会话交接统一采用三层防失真协议：

1. **程序直取硬事实**：涉及的文件路径、变更统计、关键命令与失败报错首行直接从轮次索引确定性拼装，不依赖模型复述记忆。
2. **结构化态势 + 证据句柄**：目标、现行决策、已否决方案及原因、唯一一个下一步均附带原文轮次句柄 `〔8hex#N〕`。
3. **Wire 层按需展开 + 工具下钻**：输入框只落简洁句柄或可编辑交接草稿（永不擅自替用户发送）；发给模型时经已核实的 `system-prompt/assemble` 注入结构化现场，模型需要细节时通过召回工具按句柄拉取原文。新开会话走已核实的宿主原生契约（`uiWorkspace.startSession` / `sessionController.create`）预填草稿，并在 Host 侧立即写入新会话到该「事」的硬血缘边。

## Considered Options

- **纯文本粘贴交接**：实现简单，但容易丢失硬事实、无血缘回连，且贴多会撑爆输入框与视觉区。
- **点击交接后自动发送首轮消息**：省一次回车，但失去人的最后把关权，一旦摘要有误会直接污染新会话。

## Consequences

- 复用 v1 已在真机跑稳的 `system-prompt/assemble` 展开通道、幂等账本与 `history_turn` 工具，扩展为事级上下文注入与召回。
- 回到原会话时自动区分“末尾正是本事（仅轻带下一步）”与“末尾已串台（附带事级句柄纠偏上下文）”，避免画蛇添足或串台跑偏。

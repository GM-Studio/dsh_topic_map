# 以会话主线为聚合基准，并把「待确认」作为一等信号

## Status
accepted (2026-11-27)

## Context
旧盘点是**自底向上**的：先按词面相似度把一个会话切成 6–10 个碎段，再把每个碎段各自立事。一旦语义精化失败（见 [ADR-0010](0010-semantic-refinement-reliability-and-visibility.md)），每个碎段就直接变成一张独立卡片——实测 6 个会话炸出 19–21 张碎卡，跨会话合并只成功 2 次。

真实工作区的对话分布其实是两种：
- **多数会话**整体围绕 1 件主事推进，中间穿插确认、子代理并行干活、AI 反问确认方案；
- **少数超长混杂会话**上半场干完 A 事，明确转折后去干 B 事。

同时，对话里有一个此前被完全忽略的高价值信号：**AI 向人反问、等人拍板、等人验证**（列出方案 A/B 等选择、说「我改好了请你强刷验证」、或 ask_user_question 停住）。这是「还没有结束、球在人这边」的最强铁证。

## Decision
把聚合方向反过来，改为**自顶向下、以会话主线为基准**：

1. **以会话主线为默认聚合单位**：默认 1 个工作会话 = 1 条候选主线；只在**明确话题切换**或**长间隔转折**时才拆成 2–3 段，绝不把连续工作切成十几个碎段。词面相似度降级为「辅助切分信号」，不再直接决定立事数量。
2. **四种交互全部纳入理解**：
   - 人的提问与纠偏（目标、约束、否决了什么）；
   - AI 的回答与**待确认项**（做了什么、验证过没有、是否在等人确认/测试/拍板）；
   - 折叠后的父子代理收口交付（只看父派的活与最终收口改了啥、过没过）；
   - 跨会话归并（按同一工作区内的修改文件重合、引用/分叉血缘、以及模型对会话主线的语义判断，把同一目标的多会话合成一条事）。
3. **待确认是一等状态信号**：识别到 AI 反问 / 等验证 / 等拍板时，标记该事为「待确认」，并在卡片上显式呈现「AI 正在等你：<末句摘要>」；它同时是把状态判为未收束的强证据。

拆分的唯一依据是可解释的硬信号组合（时间间隔超过阈值 + 主题漂移 + 显式转折），并记入事的证据，禁止无声拆分。

## Considered Options
- **维持自底向上碎段聚类**：切分粒度细，适合做段落级检索，但直接当立事单位会必然碎片化。
- **一个会话硬性只允许一条事**：彻底防碎，但无法处理真正的长会话转折，会把两件不相干的工作绑死。
- **只用模型做整会话归并、不做任何规则切分**：模型可用时效果好，不可用时退化为整会话一条，且无法解释为何拆分。

## Consequences
- lib/work-merge.js 的冷启动聚类从「段级相似度聚类」改为「会话主线 → 必要时转折拆分」；段仍保留，作为主线内的话题目录与证据来源。
- 轮次索引需暴露「AI 反问 / 待确认」特征（末轮是否停在等待人类回复），供切段与立事共同使用。
- 跨会话归并需要文件重合与血缘边的参与，避免只靠模型判断。

# 工作区范围、切换与跨区巡检

## Status
accepted (2026-11-27)

## Context
续接必须**以工作区为单位**：不同项目的事绝不能混成一张清单。但实机体验存在两个错位：
1. 切到另一个工作区时，界面在切换瞬间仍保留上一个工作区的数据，出现「串台」观感；
2. 其他工作区往往是第一次打开，若从未扫描过（或索引过旧），既没有自动补齐，也没有任何「正在扫描什么 / 为什么没法续接」的可见说明，用户只能看到空列表或半成品。

实测 8 个工作区中有 2 个 worksTotal 为 0（从未成功盘点），其余工作区也存在「有会话但没结果」的静默空态。

## Decision
采用「严格跟随当前工作区 + 自动补齐 + 顶部轻量巡检器」：

1. **默认严格跟随当前会话所属工作区**：进入某工作区的任意会话时，续接页立即清空上一个工作区的数据与状态（无残留、无串台），标题明确标注当前工作区。
2. **自动补齐与自动提炼**：若该工作区从未扫描、存在新会话或索引过旧，自动先补索引并触发**真正的语义提炼**，并以清晰进度状态呈现（「正在扫描工作区 X 的 N 个会话并提炼进展…」）；绝不静默拿半成品糊弄（见 [ADR-0010](0010-semantic-refinement-reliability-and-visibility.md)）。
3. **顶部提供轻量工作区切换器**：默认跟随当前工作区，人可随时切去巡检其他工作区还有哪些未收束的事，「回到现场」支持跨区直达对应会话。

工作区之间**不合并全局清单**：不做「所有工作区混排的未收束总表」。

空态必须**可区分**：未扫描 / 正在扫描 / 扫描失败 / 确实无事，四种状态呈现不同文案，不允许都显示成「暂无未收束的事」。

## Considered Options
- **只跟随当前会话工作区、不给切换器**：边界最干净，但要巡检其他工作区时得先在侧栏切区并打开一个老会话，体验别扭。
- **全局混排未收束总表**：一次看全，但不同项目的事混在一起，违背「以工作区为单位」的第一性原理，且容易误判优先级。
- **切区时保留旧数据直到新数据到达**：避免闪烁，但会让人看到错的工作区数据，正是当前被抱怨的串台感来源。

## Consequences
- 客户端续接页需要「切区即清态」的显式状态机，并把「无数据」区分为四种可见状态。
- 工作区切换器复用既有 /workspaces 端点；选中某个工作区即以其 workspaceId 驱动 /works。
- 跨区「回到现场」需要能打开目标工作区下的目标会话。

# 下一步建议与续接引导协议

## Status
accepted (2026-11-27)

## Context
实测 78 条未收束卡片中有 72 条的「下一步」是「待补充下一步行动」。一张给不出具体下一步的续接卡，本质上只是一个旧会话标题，完全不构成「续接」。这也是用户判断「事续接还是没实现好」的直接依据。

真正有用的下一步必须落到**具体对象与动作**上，并区分两个时刻：
- **看卡片那一刻**（回来做决定）：要在 3 秒内看懂「现在到哪了、为什么停、下一步干什么」。
- **点进去那一刻**（真正干活）：要让接手的人或 agent 立刻对齐现场并继续推进。

## Decision
**下一步建议（卡片层）**：

1. **模型优先**：语义提炼可用时，模型基于该事的**最后几轮真实问答**（含报错、文件变更、AI 反问与未决项）提炼出「具体现状 + 1 条主建议 + 最多 2 条备选分支」，必须带对象与动作。
2. **规则兜底不留白**：模型不可用时，规则层依据最后关键轮次给出具体线索，**禁止写「待补充」类空话**：
   - 末轮有失败报错 → 「排查第 N 轮的 <命令或报错首行>」；
   - 末轮是 AI 反问/等确认 → 「回复 AI 在第 N 轮的确认项：<末句摘要>」；
   - 末轮有文件改动 → 「核对 <文件名> 的改动并运行测试」；
   - 其余 → 「回到第 N 轮继续：<该轮目标摘要>」。

**续接引导（入口层）**：

3. **预填可执行首句**：点「回到现场」或「新会话交接」时，输入框自动预填一句已写好具体对象与目标的行动指令；**永不擅自发送**，人可改可删（见 [ADR-0004](0004-lossless-three-layer-handoff.md)）。
4. **对 AI 注入对齐协议**：Wire 层注入该事的结构化现场（目标 + 现行/已否决决策 + 改动文件与报错 + 为什么停下）时，附带一条引导规则——接手后的第一条回复必须先用极简三行确认「我已对齐现场（目标 / 卡点 / 约束）」，再直接按下一步推进或在唯一卡点上向人确认；禁止从头问「你想干什么」。

## Considered Options
- **只填输入框草稿、不注入引导行为**：实现最小，但接手 agent 可能重新从零确认需求，浪费一轮。
- **模型不可用时写「待补充下一步行动」**：诚实但无用，等于把负担推回给人，实测已经证明这是最伤体验的一环。
- **点击后自动发送首轮**：省一次回车，但失去人的最后把关权（见 [ADR-0004](0004-lossless-three-layer-handoff.md)）。

## Consequences
- 需要「末轮特征提取」：报错首行、最后命令、改动文件、AI 是否停在等待人类回复。
- 卡片必须显式呈现来源可信度（模型提炼 / 规则兜底），供人快速判断建议可靠性。
- 续接引导话术属于 Wire 注入内容，需与 ADR-0004 的三层协议一起做幂等与去重。
- 规则兜底质量必须独立达标，因为它在「模型不可用」时是唯一路径。

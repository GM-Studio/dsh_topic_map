# ADR-0011 跨工作区巡检为只读，交接是唯一例外

- 状态：已接受
- 日期：2026-11-27
- 修订：[ADR-0008](0008-workspace-scope-switching-and-inspection.md) 中「顶部轻量切换器」只当导航的部分

## 背景

为了让用户能检查别的工作区还有什么事，续接面板加了工作区切换器。随之出现一个必须回答的问题：
**切过去之后，能不能在那边改东西？**

同时暴露一个更根本的混乱：代码里同时存在三个互不相干的「当前工作区」——
会话所属工作区、面板里选中的工作区、抽屉标题显示的工作区。三者不同步，
用户切换后面板显示 A 的卡片、标题还写着 B，无法判断自己站在哪。

## 决策

### 1. 「当前工作区」只有一个定义

**当前工作区 = 打开的那个会话所属的工作区。**

面板里的选择器只改变「我在看哪个工作区的续接」，**不改变「我是谁」**，
因此不改变写权限。想在 B 区修改，唯一正当方式是**在 B 区打开一个会话**。

这条定义把「视角」与「身份」分开，只读判据才成为确定式：

> 选中工作区 ≠ 会话所属工作区 ⇒ 只读

### 2. 跨工作区一律只读

写操作会改变目标工作区的 store，而用户此时的心智上下文不在那个工作区。
看错一张卡只是浪费时间；误点「已完成」「合并」「不算事」会直接改掉另一个工作区的事态，
事后很难发现、更难回溯。代价与收益不对称，因此一律禁止。

**「写」的清单**（一律禁止）：确认 / 全部确认、改下一步、标已完成·卡住·进行中、
合并、拆段、不算事、升格为事。

**明确也算写的两个**：`重新盘点`（works-scan）与 `重试提炼`（work-refine-retry）。
它们动机上是「让数据更准」，效果上却重写了那个工作区的卡片与状态。
把它们算读，只读就名不副实。只读区可以**查看**提炼状态与失败原因，但不能触发。

**读**（一律允许）：看卡片、展开详情、看决策序列与证据、跳历史、看统计与提炼状态。

### 3. 交接是唯一被允许的写

交接会新建会话并把它绑到某个事上。跨区禁止交接，等于砍掉跨区巡检最有价值的动作——
看到 B 区有件急事却什么都做不了。

因此：**允许交接，但新会话强制创建在被巡检的那个工作区**。

这样交接成为**主动搬过去**的动作：落地后你就是 B 区的人，自然获得写权限。
这条也给出了只读的唯一出口——不是「在远方改数据」，而是「走过去」。

### 4. 前端隐藏 + 后端校验

只读是**数据完整性的不变量**，不是界面偏好。只靠隐藏按钮，等于把这个不变量
交给一次渲染结果来保证——旧标签页、并发窗口、直接调 API 都能绕过去。

因此两层都做：前端禁用并给出说明（体面），后端按「发起方会话所属工作区」校验（正确）。

### 5. 过渡期 fail-open

后端要判断「发起方是谁」，需要请求带上发起会话 id。旧标签页、脚本、
尚未升级的调用方不会带。**拿不到发起会话时按旧行为放行，并记录日志。**

理由：前端已经禁用了入口，后端这层防的是「绕过」而不是「正常使用」；
为了一个绕过场景去打断用户正在进行的一次合并，代价不对等。
确认没有旧调用方后再收紧为 fail-closed。

## 后果

- 切换器必须放在**抽屉标题栏**并由四个页签共享：切换是全局视角，
  锁在某一个页签里，用户在其它页签下就没有入口，会误以为功能不存在。
- 标题必须随选择实时变化，并在非本区时挂显眼的**只读**标记。
  标记放在标题栏而不是某张卡片上，才能让人一眼知道自己在看别人的区。
- 写按钮**禁用 + 悬停说明**，而不是隐藏：隐藏会让人以为这个区没有这些功能，
  说明才告诉他「这里不能改，要改得切回去」。
- 「待确认」角标与计数在只读区**照常显示**（真实情况，藏起来等于骗人），
  只禁用「开始逐条核对」「全部确认无误」等动作。
- 想核对必须切回原区——这是只读的固有代价，接受。

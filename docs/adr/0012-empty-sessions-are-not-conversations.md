# ADR-0012 会话是壳，对话是瓤：空会话不计入对话

- 状态：已接受
- 日期：2026-11-27

## 背景

真机上出现「切过去啥都没有」的工作区。排查发现既不是规则提取失败，也不是模型失败：

| 工作区 | 会话数 | 段数 | 事数 | 会话文件大小 |
| --- | --- | --- | --- | --- |
| afe91e6d | 1 | 0 | 0 | 413 B |
| 78c34974 | 3 | 0 | 0 | 413 / 434 / 435 B |
| cd9f719c（对照） | 6 | 13 | 3 | 一个 656 KB + 若干 |

手动跑索引构建返回 `built: 3, failed: 0`，建出来的内容是 `{ turnCount: 0 }`。
链路是：会话 0 轮 → 切不出段 → 没有簇 → **根本不调用模型** → 没有事 → 面板空。

而面板当时显示「这个工作区没有未收束的事」，读起来像「你已经都做完了」，
实际是「这里根本没有可读的东西」。**界面在撒谎。**

## 决策

### 1. 拆开两个被混用的词

- **会话（Session）**：宿主里的**标识与容器**。一定有 id、一定属于某个工作区，
  但**不保证有内容**。空会话是合法存在的。
- **对话（Conversation）**：会话里**实际发生的轮次**（≥1 轮）。空会话**没有对话**。

记法：**会话是壳，对话是瓤。空会话有壳无瓤。**

因此 **会话数 ≠ 对话数**，统计必须分开。拿容器数冒充内容数，是这次误判的直接来源。

### 2. 空会话不进对话列表，但如实计数

- **「历史检索」的对话列表不列空会话**：它不是对话，没有可读内容，有了第一轮再出现。
  代价是刚新建、还没说话的那个会话看不到——接受，因为确实没东西可读。
- **工作区统计里单列「空会话 N」，不混进「会话数」**：列表只列能读的，
  统计如实交代有多少壳是空的。
- 会话本身**不从工作区移除**：工作区是真实的，只是没有内容。

### 3. 新增 `no_content` 空态

空态从四态扩到五态：`unscanned` / `scanning` / `failed` / **`no_content`** / `empty`。

`no_content` 明确写「这个工作区的 N 个会话都没有可读对话（0 轮），所以没有可续接的事」。

### 4. 不给「重建索引」按钮

索引已经建过了，结果就是 0 轮；再建一次结果一样。给按钮等于给一个**永远不会成功的承诺**，
比没有按钮更糟。只给说明。

### 5. 「曾经有内容后被清理」与「从未有内容」不区分

对续接而言两者完全等价——都没有可接的东西。而且目前拿不到可靠证据去区分，
硬做只能靠猜，又会回到「把不知道说成知道」的老毛病。代价是：某段历史真被清理时，
界面上看不出「曾经有过」。

## 后果

- `/workspaces` 与 `/works` 必须显式给出「有对话的会话数」与「空会话数」，
  前端不再自行从 `sessionIds.length` 推断。
- 续接面板不得再把「没有内容」说成「没有未收束的事」。

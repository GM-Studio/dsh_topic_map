## 1. 结论

| 定位 | 判定 |
|---|---|
| 作为「历史对话的**语义导航器**」 | **较完善，可日常使用** |

## 2. 评审方法

不采用"读代码猜能力"，而是三类实证：

1. **代码事实**：核对常量、字段、交互路径（如 `lib/turn-model.js` 的 `pathsOf`、`lib/client.js` 的 `VIRT_MIN_NODES`）。
2. **真实日志核查**：解压当前工作区一个会话的日志，统计事件类型与工具调用的实际形状。
3. **平台契约核查**：用 Cordis Inspect 读取 Host/Client 服务签名与类型声明，确认"平台已经提供了什么"。

## 4. 平台能力盘点（决定可行性）

通过 Cordis Inspect 核实，与"历史对话管理"直接相关的契约：

| 服务 / API | 能力 | 对需求的含义 |
|---|---|---|
| `workspaceChanges.summary(sessionId, seq)` | `{ turn, cwd, files[{path, display, added, deleted, binary?, oversized?}], total, added, deleted, snapshot? }` | **"哪些文件变更"可直接获得，带 ±行数** |
| `workspaceChanges.diff(sessionId, seq, index, signal)` | 真实 diff：`hunks[{oldStart, oldLines, newStart, newLines, lines}]`，或 binary / oversized | **"改成什么样"可直接获得** |
| `fs.writeText(target, content, expected?, signal?, policy?)` | 带 `FsWriteIntent` 的安全写入 | 回滚的写入口 |
| `fs.editText(target, edit, expected?: {version})` | 带版本校验的编辑 | **回滚可防覆盖外部改动** |
| `sessions.fork({ sessionId, atSeq?, increaseTitle?, onCreated?, allowMigration? })` | 从精确某一轮（inclusive prefix）派生新会话 | **"基于版本新开会话"完全可行** |
| `ISession.prompt(content, mode, signal?, requestId?)` / `beginSubmission` | 编程式发送提问 | fork 后可预填输入 |
| `sessions.search(query, signal)` | 平台内建消息内容索引 | 可替换现有 O(n) 日志扫描（需确认部署是否开启索引） |
| `worktrees.create(agent, request)` | 创建受管 Git worktree | 更安全的隔离实验环境 |
| `workingDirectory` | 每会话有效目录与变更 | 回滚时的相对路径基准 |
| **restore / checkpoint / undo 服务** | **不存在** | **回滚必须自研** |

### 4.1 平台已有 UI，不应重复实现

DSH 自带客户端插件 `ui-deliverables`（标题「文件变更与交付展示」）已经在对话里渲染
"改过的文件 + 内容对比"。因此：

- **不要**重写 diff 渲染器；
- 本插件的增量价值在于**跨轮次、跨会话的聚合**（"这个文件被哪些轮改过"）与**对结果的动作**（回滚 / fork）。

## 5. 关键风险：文件变更摘要是易失的

`workspaceChanges` 契约明确：

> returns undefined **once its Session was disposed**, or **when this Host never recorded it**

日志中的 `workspace/changes` 事件只携带 `{ turn }`（指针），**不含文件清单**；明细由内存中的 recorder 持有。

**后果**：若不在"看到它的那一刻"落盘，历史会话的文件变更将永久丢失。
**越晚实施，可覆盖的历史越少。**

因此这不是一个普通功能，而是**数据地基**，优先级最高。

## 6. 缺口分析（逐条对应用户问题）

### 6.1 "要知道历史对话做了什么、产生了什么结果"

| 现状 | 应为 |
|---|---|
| 仅 `endReason`（completed / error / max-tokens 等） | 每轮：工具调用成败、结构化错误码、产物、文件变更 |
| `files` 由正则扫参数得出，含只读路径，上限 8 | 使用 `workspaceChanges.summary` 的精确清单与 ±行数 |

### 6.2 "哪些文件变更了"

现状 10%。改造要点：

1. 解析 `workspace/changes` 事件取 `seq`；
2. 调 `workspaceChanges.summary(sessionId, seq)` 拿清单；
3. **立即落盘**（见第 5 节），形成本插件自己的变更账本；
4. 右栏展示 + 图上标记有变更的轮次。

### 6.3 "能不能重置 / 恢复 / 回滚"

现状 0%。可恢复性**本质上三态**：

| 变更来源 | 可恢复性 | 本会话占比 |
|---|---|---|
| `edit`（有 old_string） | ✅ 精确反向替换 | 837 / 4525 次调用 |
| `write`（有全文） | ⚠️ 需回放到上一版本 | 265 次 |
| `ops_bash` 内 sed/mv/rm | ❌ 不可知 | 2292 次 |
| 用户手工编辑 | ❌ 不在日志 | — |

### 6.4 "基于这个历史对话的版本新开一个会话"

现状 0%。平台 `sessions.fork({ sessionId, atSeq })` 直接支持"从某一轮的 inclusive prefix 派生"，
配合 `ISession.prompt` 可预填首条输入。

### 6.5 "还有没有其他可做的"

见第 7 节分层；其中最高价值的是**按文件反向索引**（见 8.2）。

## 7. 功能分层

### 7.1 核心闭环（不做即半成品）

| # | 功能 | 理由 | 成本 |
|---|---|---|---|
| C1 | 每轮文件变更（精确，替代正则猜测） | "结果"与"回滚"的共同基础 | 中 |
| C2 | 变更摘要落盘 | 否则历史数据永久丢失（第 5 节） | 小 |
| C3 | 右栏「变更」区块（文件 + ±行数） | 让 C1 立即可见 | 小 |
| C4 | 图上标记有文件变更的轮次 | 一眼看出"哪几轮是实干的" | 小 |
| C5 | 基于某轮 fork 新会话（可预填输入） | 平台现成，最高频的"重来一次" | 小 |

### 7.2 增强（做完才算完善）

| # | 功能 | 价值 | 风险 |
|---|---|---|---|
| E1 | 按文件反向索引：文件 → 哪些轮/会话改过 | "统一管理"的另一半维度 | 中 |
| E2 | 工具成败可视化（失败轮次标红、错误码可读） | 把"结果"从推测变事实 | 小 |
| E3 | 交付物聚合视图 | 复用 `ui-deliverables` 数据 | 中 |
| E4 | 多文件批量回滚 | 用户明确要求 | **大且危险**，见第 9 节 |
| E5 | 任意两轮之间的工作区对比 | 复盘"这半天改了什么" | 中 |

### 7.3 不建议做

| 功能 | 理由 |
|---|---|
| 一键回滚整个会话的全部文件 | bash 改动不可逆；会给出"已恢复"的错误安全感 |
| 自建定期全工作区快照 | 磁盘与性能代价大；平台已有 worktree |
| 重写 diff 渲染器 | 平台有 `ui-deliverables`，重复造会长期落后 |
| 跨工作区聚合 | 违背当前边界设计，收益低 |

## 9. 多文件批量回滚：设计规程

> 用户已选定该形态。以下为必须遵守的约束，否则会变成"看起来恢复了、其实没恢复"的陷阱。

### 9.1 三态报告（不可折叠为"成功/失败"）

```
✓ 已恢复     lib/client.js        -40 +5
✓ 已恢复     lib/index.js         -12 +3
⚠ 部分恢复   docs/README.md       仅恢复了 edit 部分；另有一次 bash 改动无法回滚
✗ 未恢复     deploy.sh            只通过 bash 修改过，日志里没有内容
✗ 已跳过     lib/theme.js         文件在此期间被外部修改，拒绝覆盖
```

`⚠ 部分恢复` 与 `✗ 未恢复` **必须显式逐条列出并说明原因**。

### 9.2 执行规程

1. **预演（只读）**：扫出这批文件的全部变更 → 计算"撤销后内容" → 展示三态报告与总 ±行数。
2. **确认**：界面必须显示"有 N 个文件无法恢复"，用户确认后才可继续。
3. **执行**：逐文件写入，每个都用 `fs.editText(expected: { version })`；
   版本不匹配（文件被动过）→ 跳过并记 `已跳过`，**绝不覆盖**；每个文件写成功即记一行执行日志，中断可续。
4. **可撤销**：保留"撤销本次回滚"的能力（写前版本留档），否则回滚本身不可撤销。

### 9.3 前置依赖

批量回滚**必须先完成 C1/C2**。否则：

- `workspaceChanges` 对历史会话返回 `undefined`；
- 只能靠重放 `edit`/`write` 参数，而 `write` 的旧内容需要从头回放整个会话，误判率随会话变长上升。
